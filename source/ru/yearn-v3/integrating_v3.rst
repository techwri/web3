Интеграция хранилищ V3
=======================

Версия V3 предоставляет интеграторам все те же преимущества, что и V2, но с расширенными возможностями и стандартизацией.

Хранилища
---------

Все хранилища V3, как мультистратегийные, так и одностратегийные, полностью соответствуют стандарту :term:`ERC-4626`, что упрощает и стандартизирует интеграции

Депозиты
--------

Депозиты соответствуют стандартному потоку 4626. Рекомендуется использовать ``deposit`` вместо ``mint`` при внесении средств в хранилище Yearn.

.. code-block:: solidity

   token.approve(vault, amount);
   vault.deposit(amount, receiver);

Также доступен маршрутизатор ``4626 Router`` для упрощения многошаговых пользовательских операций.

Максимальную сумму, которую хранилище готово принять от адреса, можно получить через функцию ``maxDeposit``.

Вывод средств
-------------

Функции вывода, соответствующие 4626, работают для всех хранилищ V3, однако рекомендуется использовать ``redeem`` вместо ``withdraw``.

Дополнительные параметры
~~~~~~~~~~~~~~~~~~~~~~~~

Хранилища V3 поддерживают дополнительные параметры при выводе средств.

**maxLoss**
^^^^^^^^^^^

Параметр ``maxLoss`` применяется в функциях ``withdraw`` и ``redeem`` и указывается в базисных пунктах. Он определяет максимально допустимые потери при выводе. Если потери превышают это значение, транзакция будет отменена.

.. note::

   - ``redeem`` по умолчанию допускает любые потери (``maxLoss = 10000``)
   - ``withdraw`` по умолчанию не допускает потерь (``maxLoss = 0``)

.. code-block:: solidity

   balance = vault.balanceOf(user);
   vault.redeem(balance, receiver, user, maxLoss);

.. warning::

   Рекомендуется всегда явно указывать ``maxLoss`` в финальной стадии вывода.

**strategies**
^^^^^^^^^^^^^^

Мультистратегийные хранилища могут принимать параметр ``strategies`` — массив (до 10) адресов стратегий, из которых будет осуществляться вывод. Этот список переопределяет ``default_queue``, если ``use_default_queue`` установлен в ``false``.

.. code-block:: solidity

   strategies = [compoundLender, aaveLender];
   balance = vault.balanceOf(user);
   vault.redeem(balance, receiver, user, 1, strategies);

Максимально допустимая сумма для вывода или погашения также может быть получена через ``maxRedeem`` и ``maxWithdraw``. Эти функции также могут принимать дополнительные параметры.

Ценообразование
---------------

Оценка стоимости токенов хранилища осуществляется через стандартные функции ``convertToShares`` и ``convertToAssets``.

Хотя Yearn старается предотвратить манипуляции с функциями конверсии, при использовании их внутри других протоколов следует учитывать риски. Подробнее см. :doc:`v3-token-collateral`.

Хранилища V3 также включают устаревшую функцию ``pricePerShare`` из V2, но она предназначена только для оффчейн-применения — не рекомендуется использовать её в ончейн-логике из-за потери точности.

Периферийные контракты
----------------------

Существует несколько периферийных контрактов, полезных для получения информации о хранилищах в сети.

Реестр (Registry)
~~~~~~~~~~~~~~~~~

* ``getAllEndorsedVaults()`` — вложенный массив, отсортированный по активам.
* ``getEndorsedVaults(address _asset)`` — список хранилищ для конкретного актива.
* ``vaultInfo(address _vault)`` — структура Info: базовый актив, версия релиза, дата развёртывания, тип хранилища, теги.

Менеджер ролей (Role Manager)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Управляет мультистратегийными хранилищами, обладает правами ``role_manager``.

Можно получить связанные контракты через:

* ``getBrain()``
* ``getRegistry()``
* ``getPositionHolder(keccak256("Brain"))``
* ``getDebtAllocator(vault)``
* ``getAllVaults()`` — список всех управляемых хранилищ
* ``getVault(asset, apiVersion, category)`` — возвращает конкретное хранилище по параметрам.

Категория (Category)
~~~~~~~~~~~~~~~~~~~~

В V3 появилось понятие ``category`` — для различения нескольких хранилищ на один и тот же актив.

Значение категории добавляется к имени и символу хранилища, указывая тип. Например, ``1`` — самый низкий риск, ближе всего к стилю V2-хранилищ.
